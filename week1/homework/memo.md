Decision Memo: Synthetic Retinal Fundus Image Generator
Recommendation
I recommend using a class-conditional latent diffusion model that is fine-tuned from an already trained model instead of building one from scratch.
The main reason for this choice is that we only have 800 real retinal images and a limited training budget of 40 hours on a single A10G GPU. Training a model from scratch with such a small dataset would be difficult because it would not have enough examples to properly learn all the details of retinal images. Starting with a pretrained diffusion model gives us a better starting point because it has already learned general image patterns. We can then fine-tune it using our retinal images. We could also use LoRA to reduce training time and memory usage.
Another reason is that our dataset has an uneven number of images across the different severity classes. By using class conditioning we can tell the model which severity level to generate. This allows us to create more images for classes that have fewer real examples. Diffusion is also a good choice because it can generate detailed images. This is important when dealing with small retinal features such as microaneurysms and tiny hemorrhages.
Main Failure Mode and How to Detect It
The biggest risk is that the model generates images that look realistic but do not actually match their assigned severity labels. For example it might generate an image labelled as severe diabetic retinopathy even though the image only shows mild signs of the disease. This is dangerous because the classifier could learn incorrect patterns and fail to identify patients with more serious conditions.
To prevent this I would use three checks before allowing the images into the training dataset. First I would compare generated images with the original training images using feature similarity to identify possible copies. Second I would ask an ophthalmologist to review a sample of generated images and check whether their severity matches the assigned label. Finally I would use a classifier trained only on real images to predict the severity of the synthetic images and compare its predictions with the requested labels. Images that fail these checks should not be used.
Why Not GANs or VAEs?
I would not choose a GAN because our dataset is too small especially for the rare severity classes. GANs can struggle when there are not enough examples and may start memorising the training images instead of generating new ones. They can also suffer from mode collapse which means they produce very similar images repeatedly. This would be a problem because we need variety especially for the underrepresented classes.
I would also avoid a VAE for this task. Although VAEs are easier and cheaper to train they often produce blurry images because their reconstruction process can smooth out small details. In retinal images details such as tiny hemorrhages and microaneurysms are important for identifying disease severity. If these details become blurry or disappear the generated images may not be useful for training a reliable classifier.
Evaluation Metric Beyond FID
I would use per-class sensitivity as the main evaluation metric. This measures how well the classifier identifies actual cases of each severity level. I would compare a classifier trained using only real images against one trained using both real and synthetic images. I would pay particular attention to the moderate and severe classes because missing these cases could have serious consequences.
FID alone is not enough because it mainly measures how similar generated images look to real images. It does not tell us whether the images have the correct disease severity or contain the important retinal features. An image could look realistic but still have the wrong label. For this reason checking sensitivity on real images gives us a better idea of whether synthetic data actually improves the classifier without making it less safe.
